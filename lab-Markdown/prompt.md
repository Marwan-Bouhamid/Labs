# Role
You are a technical writer and senior web developer who specializes in clear, professional documentation.

# Context
I am a web development student completing a Markdown lab. I must write a single Markdown document (README.md) that presents my **technical project**. My repository is:
https://github.com/Marwan-Bouhamid/Projet-technique

The source code is spread across **multiple branches**, not only the default one. Before writing, inspect every branch (file structure, README files, commit history, dependencies) so that the document reflects the real project and nothing is invented. If something cannot be verified from the repository, insert a clearly marked placeholder such as `[TO COMPLETE: ...]` instead of guessing.

# Task
Write a complete, well-organized Markdown document that presents:

1. **Project Subject:** what the project is about, the problem it addresses, and its context.
2. **Project Objective:** the goal of the project, what it should achieve, and for whom.

# Mandatory Markdown Elements
The document MUST demonstrate each of the following, used naturally and meaningfully (not as filler):

- Headings (multiple levels) and paragraphs
- **Bold**, *italic*, and ~~strikethrough~~ text
- Bulleted lists and numbered lists
- Task lists (checkboxes) showing project progress or features
- Links (including the GitHub repository and its branches) and images (e.g., a screenshot or logo)
- Tables (e.g., technologies used, branch overview, or feature status)
- Inline code and fenced code blocks with language tags (e.g., install or run commands, a code excerpt from the repo)
- Blockquotes (e.g., a project motto or key principle)
- Horizontal rules to separate major sections

# Suggested Structure
1. Title and short tagline
2. Project Subject
3. Project Objective
4. Technologies used (table)
5. Repository and branches overview (table with link to each branch)
6. Main features / progress (task list)
7. Installation and usage (numbered list and code blocks)
8. Conclusion

# Quality Requirements
- Professional, concise, and easy to read; formal but not overly wordy
- Accurate: base all content on the actual repository
- Valid Markdown that renders correctly on GitHub
- Consistent formatting, correct heading hierarchy, and no broken links

# Output
Return only the final Markdown document in a single code block, followed by a short list of any placeholders I still need to fill in.
